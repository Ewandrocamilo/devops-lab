The portfolio is a static website. The browser downloads files from CloudFront, which reads the private S3 origin.

Context behind the implementation

Technical decisions

Small choices that keep the lab practical, explainable, and easy to evolve.

Architecture choices

Static site
Host the portfolio as static files

The dashboard uses HTML, CSS, and browser-side navigation, so it does not need a continuously running server.

Keep the S3 bucket private

CloudFront Origin Access Control reads the bucket; visitors reach the site through the CDN.

Deploy with GitHub OIDC

The workflow assumes an IAM role and stores no long-lived AWS access keys.

Keep lab services separate

The API and database remain available for learning, but the public site does not query or depend on them.

Trade-offs and next increments

No live infrastructure telemetry

The site describes the lab but does not claim current health for EC2, Kubernetes, or a database.

CDN cache must be refreshed

The deployment workflow creates an invalidation after publishing the page.

CloudFront URL first

A custom domain can be attached later; DNS and domain registration remain separate concerns.

Future work

Add a custom domain, visual regression checks, or project documentation as the portfolio grows.

Operational notes

Troubleshooting & lessons

Documenting what breaks, how it was investigated, and what the lab taught along the way.

Website deployment checks

CloudFront returns an old pageCheck

Confirm the GitHub Actions run succeeded and verify the invalidation completed for the distribution.

Access denied at the CloudFront URLCheck

Check the S3 bucket policy source ARN and ensure the distribution uses the matching Origin Access Control.

Workflow cannot upload the pageCheck

Verify the repository variables match Terraform outputs and the GitHub OIDC role has the scoped deploy policy.

What this lab practices

01
Diagnose before changing

Gather configuration and execution evidence before applying a fix.

02
Make access explicit

Private origins and scoped IAM policies limit who can publish and serve site files.

03
Automate repeatable work

Terraform provisions hosting; GitHub Actions publishes each reviewed change.

04
Capture the learning

Troubleshooting notes turn a one-time incident into a reusable runbook.
